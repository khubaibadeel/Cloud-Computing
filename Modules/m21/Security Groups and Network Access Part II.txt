

# Security Groups and Network Access Part II:
    This lecture explains stateful behavior, rule syntax, Security Group references,
    best practices, and basic troubleshooting.


    # Stateful Behavior:
        "Security Groups are stateful."

        This means:
            - Return traffic is automatically allowed.
            - You do not need to create separate mirror rules for response traffic.

        Examples:
            1. If an inbound request is allowed,
                --> the outbound reply is automatically allowed.

            2. If an outbound request is allowed,
                --> the inbound reply is automatically allowed.


    # Stateful Practical Example:
        Example: A user opens a website.

        1. User sends an HTTP request to Port 80.
            - The request is allowed by the inbound rule.

        2. Server sends the response back to the user.
            - No separate outbound reply rule is needed.

        3. The Security Group automatically tracks the connection state.


    # Security Group Rule Syntax:
        A Security Group rule normally contains these fields:

        1. Type
            - A preset label for common traffic.

            Examples:
                - HTTP
                - SSH
                - RDP
                - MySQL
                - Custom TCP

        2. Protocol
            Examples:
                - TCP
                - UDP
                - ICMP
                - All

        3. Port Range
            Examples:
                - Single Port --> 22
                - Port Range --> 8000-9000
                - All Ports --> -1

        4. Source / Destination
            - Defines where traffic comes from or goes to.

            It can be:
                - An IP address
                - A CIDR block
                - A Security Group ID


    # Using a Security Group as Source:
        Instead of using an IP address, you can use another Security Group as the source.

        Example:
            Database Security Group Inbound Rule:
                - Protocol --> TCP
                - Port --> 3306
                - Source --> WebServer-SG

        Result:
            - Only instances associated with WebServer-SG can connect to the database.

        # Benefit:
            - More flexible than using fixed IP addresses.
            - Instance IP addresses can change.
            - Security Group references continue to work based on group membership.


    # Best Practices:
        1. Follow Least Privilege
            - Allow only the traffic that is actually required.

        2. Protect SSH
            - Never open Port 22 to 0.0.0.0/0 unless absolutely necessary.
            - Prefer your own trusted IP or network.

        3. Use Clear Security Group Names
            Examples:
                - WebServer-Public-SG
                - Database-Private-SG

        4. Use One Security Group Per Role
            - Keep web, database, admin, and other access rules separated when possible.

        5. Review Rules Regularly
            - Remove unused or unnecessary rules.
            - Keep access as restricted as possible.


    # Troubleshooting Checklist:
        # Problem 1: Website Does Not Load
            Check:
                - TCP Port 80 for HTTP
                - TCP Port 443 for HTTPS
                - Correct inbound source

            Public websites commonly use:
                - Source --> 0.0.0.0/0

        # Problem 2: Cannot SSH
            Check:
                - TCP Port 22 is allowed inbound.
                - Source matches your current public IP.
                - Do not assume your public IP is always the same.

        # Problem 3: Application Cannot Reach Database
            Check:
                - Database Security Group inbound rule.
                - Correct database port.

            Common Database Ports:
                - MySQL --> 3306
                - PostgreSQL --> 5432

            Recommended Source:
                - Use the Web Server Security Group as the source.


    # Quick Summary:
        1. Security Groups are stateful.
            --> Return traffic is automatically allowed.

        2. No mirror rules are required.
            --> Response traffic is automatically handled.

        3. A rule contains:
            - Type
            - Protocol
            - Port Range
            - Source / Destination

        4. Security Groups can reference other Security Groups.
            --> Useful for web-to-database communication.

        5. Use least privilege.
            --> Allow only required traffic.

        6. Keep SSH restricted.
            --> Prefer your IP instead of 0.0.0.0/0.

        7. Common ports:
            - HTTP --> 80
            - HTTPS --> 443
            - SSH --> 22
            - MySQL --> 3306
            - PostgreSQL --> 5432


    # Lecture Summary:
        "Security Groups are stateful, so return traffic is automatically allowed.
        Use clear and restricted rules, reference other Security Groups when useful,
        and troubleshoot access by checking protocol, port, and source."
