# Amazon S3 Fundamentals Part I:
    This topic introduces Amazon S3 and explains how object storage differs
    from other AWS storage options such as Amazon EBS and Amazon EFS.

    It covers:
        - Block storage
        - File storage
        - Object storage
        - S3 objects and buckets
        - Object keys and metadata
        - S3 URL structure
        - Flat namespace
        - S3 scalability
        - Multipart upload
        - S3 vs traditional storage


    # Three Common AWS Storage Types:
        AWS provides different storage models for different use cases.

        The three storage types discussed are:

            1. Block Storage
                --> Amazon EBS

            2. File Storage
                --> Amazon EFS

            3. Object Storage
                --> Amazon S3


    # Amazon EBS:
        EBS stands for:

            Elastic Block Store

        EBS provides block-level storage.

        Simple idea:
            - Think of it like a virtual disk.

        Main Characteristics:
            - Operates at disk/block level.
            - Commonly attached to an EC2 instance.
            - Provides low-latency storage.
            - Can contain normal file systems.
            - Suitable for operating systems, applications, and databases.

        Example:
            EC2 Instance
                --> EBS Volume
                --> File System
                --> Files and Folders


    # Amazon EFS:
        EFS stands for:

            Elastic File System

        EFS provides file storage.

        It behaves like a shared file system with:

            - Files
            - Folders
            - Subfolders
            - File hierarchy

        Main Benefit:
            - The same EFS file system can be shared across multiple servers.

        Example:
            EC2 Server A
                --> EFS

            EC2 Server B
                --> Same EFS

            EC2 Server C
                --> Same EFS

        Result:
            - A file created through one connected server can be available
              to the other servers using the same file system.


    # Amazon S3:
        S3 stands for:

            Simple Storage Service

        Amazon S3 provides object storage.

        Unlike EBS and EFS:
            - S3 is not used like a normal local disk.
            - It does not use a traditional file-system hierarchy.
            - Objects are stored inside buckets.
            - Objects are identified by keys.

        S3 is designed for:
            - Very large scale.
            - High durability.
            - API-based access.
            - HTTP/HTTPS access.
            - Storing almost any type of file or object.


    # Object Storage:
        Object storage stores data as individual objects.

        Each object is a self-contained unit.

        An object commonly includes:

            1. Data
            2. Metadata
            3. Key


    # What is Object Data?
        Data is the actual content of the object.

        Examples:
            - Text inside a .txt file
            - Pixels inside an image
            - Video content
            - PDF content
            - ZIP archive data
            - Backup data


    # What is Metadata?
        Metadata means:

            "Information about the data."

        Examples can include:
            - Content type
            - Object size
            - Last modified information
            - Checksum information
            - User-defined metadata

        Metadata helps describe and manage an object.


    # What is an Object Key?
        The object key is the unique name of an object inside a bucket.

        Example:

            images/logo.png

        Here:

            Bucket:
                --> Holds the object.

            Object Key:
                --> images/logo.png

        Important:
            - The complete string is the object's key.
            - The slash does not necessarily mean a real folder exists.


    # Simple Object Example:
        Object:
            Key:
                --> documents/report.pdf

            Data:
                --> Actual PDF file contents

            Metadata:
                --> Content type, size, checksum, and other information


    # Block Storage vs Object Storage:
        Block Storage:
            - Works like a disk.
            - Attached to a server.
            - Supports a traditional file system.
            - Designed for low-latency reads and writes.

        Object Storage:
            - Stores complete objects.
            - Accessed through APIs and HTTP/HTTPS.
            - Each object has a unique key.
            - Scales to extremely large amounts of data.


    # Postal Warehouse Analogy:
        A useful analogy is:

        Block Storage:
            - Like a local hard drive attached to your computer.
            - Fast and directly attached.
            - Contains files and folders.

        Object Storage:
            - Like a giant warehouse containing packages.
            - Each package has a unique tracking number.
            - Packages can be accessed independently.
            - Capacity can grow to a very large scale.

        In this analogy:
            Package
                --> Object

            Tracking Number
                --> Object Key

            Warehouse
                --> S3 Bucket


    # What is an S3 Bucket?
        An S3 bucket is a container for S3 objects.

        It is a top-level organizational unit in Amazon S3.

        Structure:

            S3 Bucket
                --> Object 1
                --> Object 2
                --> Object 3
                --> ...


    # Bucket Naming:
        General purpose S3 bucket names must be unique within the AWS partition
        in which the bucket is created.

        Examples of AWS partitions include:
            - Standard AWS
            - AWS GovCloud
            - AWS China

        Practical meaning:
            - You cannot create another general purpose bucket with the same name
              if that name is already in use in the same partition.


    # Bucket Region:
        When creating a bucket:

            1. Choose a bucket name.
            2. Choose an AWS Region.

        Important:
            - The bucket's Region cannot simply be changed after creation.
            - To move data to another Region, you generally create another bucket
              in the target Region and copy or replicate the data.


    # Current General Purpose Bucket Quota:
        AWS currently allows:

            Default:
                --> Up to 10,000 general purpose buckets per AWS account.

        The quota can be increased through AWS Service Quotas.

        Important:
            - Older AWS training material may mention a default limit of 100 buckets.
            - That older number is no longer the current default.


    # Why Bucket Names Must Be Unique:
        S3 bucket names can appear as part of DNS-style service endpoints.

        Example idea:

            https://BUCKET-NAME.s3.REGION.amazonaws.com/OBJECT-KEY

        Because the bucket name participates in the endpoint name:
            - It must uniquely identify the bucket.


    # S3 URL Structure:
        A common virtual-hosted-style S3 URL looks like:

            https://digiskills-course-assets.s3.ap-south-1.amazonaws.com/images/logo.png

        Parts:

            https://
                --> Protocol

            digiskills-course-assets
                --> Bucket Name

            s3
                --> S3 Service

            ap-south-1
                --> AWS Region

            amazonaws.com
                --> AWS Domain

            images/logo.png
                --> Object Key


    # Important - The Object Key is Not a Real Folder Path:
        Consider:

            images/logo.png

        In a traditional file system:
            images
                --> Folder

            logo.png
                --> File

        In S3:
            images/logo.png
                --> One complete object key

        The slash character is part of the key name.


    # S3 Has a Flat Namespace:
        S3 object storage is logically flat.

        Example keys:

            images/logo.png
            images/banner.jpg
            backups/db-01.sql
            reports/2026/june.pdf

        S3 stores these as separate object keys.

        The AWS Console may display:

            images/
            backups/
            reports/

        But these are primarily prefixes used to organize object keys visually.


    # Prefixes:
        A prefix is the beginning portion of an object key.

        Example:

            Object Key:
                images/logo.png

            Prefix:
                images/

        Prefixes allow:
            - Logical grouping
            - Easier browsing
            - Filtering objects
            - Organizing large collections of objects


    # S3 Scale:
        Amazon S3 is designed to scale to extremely large amounts of data.

        A bucket can store:

            - Any number of objects.

        You do not normally provision a fixed bucket capacity in advance.

        Concept:
            --> Storage grows as objects are added.


    # Maximum Object Size:
        Current AWS documentation allows a single S3 object to be approximately:

            50 TB
            or
            48.8 TiB

        Important:
            - Older AWS material commonly states a 5 TB maximum object size.
            - AWS has since increased the maximum object size.

        Console uploads have a lower per-object upload limit than the full
        multipart-upload capability.


    # Single PUT Upload:
        A normal single PUT operation can upload an object up to:

            5 GB

        Larger uploads should use multipart upload.


    # Multipart Upload:
        Multipart upload divides one large object into multiple parts.

        Process:

            Large File
                --> Part 1
                --> Part 2
                --> Part 3
                --> ...

            Parts Upload
                --> Independently / In Parallel

            Amazon S3
                --> Assembles Parts

            Final Result
                --> One Complete Object


    # Why Use Multipart Upload?
        Benefits:

            1. Faster upload through parallel transfers.
            2. Failed parts can be retried separately.
            3. Large files do not need to restart from zero after one failure.
            4. Uploads can be more resilient on unstable networks.


    # Multipart Upload Recommendation:
        AWS recommends considering multipart upload when an object reaches:

            --> 100 MB or larger.

        Important:
            - S3 itself does not automatically convert every upload above 100 MB
              into multipart upload.
            - AWS CLI, SDKs, transfer managers, or applications can use multipart
              upload automatically depending on the tool and configuration.


    # Multipart Upload Limits:
        Current multipart-upload limits include:

            Maximum parts:
                --> 10,000

            Part size:
                --> 5 MiB to 5 GiB

            Exception:
                --> The final part can be smaller than 5 MiB.

        After all parts are uploaded:
            - Amazon S3 assembles them into one object.


    # S3 Does Not Require Attachment to a Server:
        EBS and EFS are normally mounted or attached for server-based use.

        S3 is different.

        You can access S3 through:

            - AWS Management Console
            - AWS CLI
            - AWS SDK
            - REST API
            - HTTPS requests
            - Applications

        Therefore:
            - S3 does not have to be attached as a normal disk first.


    # Internet Accessibility:
        S3 service endpoints can be reached over HTTPS when network access
        and permissions allow it.

        Important:
            - This does NOT mean every S3 object is publicly accessible.
            - S3 buckets and objects are private by default unless permissions
              explicitly allow public or other authorized access.


    # Partial File Editing:
        Traditional file systems can modify portions of a file.

        With a normal S3 object:

            - You generally replace the object when its content changes.
            - S3 is not designed like a normal random-access file system.

        Example:

            Existing:
                report.pdf

            Modified:
                report.pdf

            Typical S3 operation:
                --> Upload the updated complete object.


    # EBS / EFS vs S3:
        # EBS / EFS:
            - Used as block or file storage.
            - Provides file-system-style access.
            - Commonly mounted or attached.
            - Capacity and file-system behavior depend on the service/configuration.
            - Suitable for workloads needing traditional file-system access.

        # S3:
            - Object storage.
            - Accessed through API/HTTP methods.
            - Uses buckets and keys.
            - No true traditional folder hierarchy.
            - Extremely scalable.
            - Objects are normally replaced rather than partially edited.


    # Quick Comparison:
        1. Amazon EBS
            - Type --> Block Storage
            - Main Idea --> Virtual disk
            - Server Attachment --> Yes
            - File Hierarchy --> Through a file system
            - Strength --> Low-latency block access

        2. Amazon EFS
            - Type --> File Storage
            - Main Idea --> Shared file system
            - Server Attachment/Mount --> Yes
            - File Hierarchy --> Yes
            - Strength --> Shared access across multiple servers

        3. Amazon S3
            - Type --> Object Storage
            - Main Idea --> Bucket + Objects
            - Server Attachment --> Not required
            - File Hierarchy --> No real hierarchy
            - Access --> API / HTTP / HTTPS
            - Strength --> Massive scale and object-based storage


    # When to Use EBS:
        EBS is suitable for:

            - EC2 boot volumes
            - Databases
            - Application disks
            - Low-latency workloads
            - Traditional file systems on EC2


    # When to Use EFS:
        EFS is suitable for:

            - Shared application files
            - Multiple Linux servers
            - Shared content
            - File-system workloads
            - Applications requiring hierarchical file access


    # When to Use S3:
        S3 is suitable for:

            - Images
            - Videos
            - Documents
            - Backups
            - Logs
            - Static website files
            - Data lakes
            - Application assets
            - Archives
            - Large-scale object storage


    # Important Concept:
        S3 is not automatically "better" than EBS or EFS.

        They solve different problems.

        Choose storage based on:

            - Access pattern
            - Performance requirement
            - File-system requirement
            - Sharing requirement
            - Scalability
            - Application design


    # Quick Summary:
        1. EBS
            --> Block storage similar to a virtual disk.

        2. EFS
            --> Shared hierarchical file storage.

        3. S3
            --> Object storage.

        4. S3 Object
            --> Data + Metadata + Key.

        5. S3 Bucket
            --> Container that stores objects.

        6. Object Key
            --> Unique object name inside the bucket.

        7. S3 Namespace
            --> Logically flat.

        8. Slash in Key
            --> Part of the object key, not necessarily a real folder.

        9. Bucket Region
            --> Selected when the bucket is created.

        10. Default General Purpose Bucket Quota
            --> 10,000 per AWS account.

        11. S3 Capacity
            --> No fixed bucket-size limit and any number of objects.

        12. Maximum Object Size
            --> Approximately 50 TB / 48.8 TiB.

        13. Multipart Upload
            --> Splits large objects into parts for upload.

        14. 100 MB
            --> AWS recommends considering multipart upload at this size.

        15. S3 Access
            --> Console, CLI, SDK, API, and HTTPS.


    # Lecture Summary:
        "Amazon S3 is highly scalable object storage that stores data as objects
        inside buckets. Each object contains data, metadata, and a key. Unlike
        EBS and EFS, S3 does not use a traditional file-system hierarchy and does
        not need to be attached to a server before use. Object keys may contain
        slash characters for logical organization, but S3 remains a flat object
        namespace. S3 is designed for massive scale and supports multipart upload
        for large objects."
