

# S3 Lifecycle Policies and Versioning Part II:
    This topic explains how S3 versioning creates current and noncurrent object
    versions, and how lifecycle rules, delete markers, MFA Delete, Object Lock,
    and replication help protect and manage versioned data.


    # Current and Noncurrent Versions:
        With S3 Versioning enabled:

            - Every upload creates a new version.
            - The latest version becomes the current version.
            - Older versions become noncurrent versions.
            - Every version has a unique Version ID.

        Important:
            - Noncurrent versions are still stored.
            - They can continue adding storage cost.


    # Lifecycle Rules for Noncurrent Versions:
        Lifecycle rules can manage old versions in three ways:

        1. Transition
            - Move noncurrent versions to cheaper storage after N days.

        2. Permanent Delete
            - Delete noncurrent versions after N days.

        3. Delete Markers
            - Remove expired object delete markers.

        Example:
            New upload
                --> Current in Standard

            Old version
                --> Becomes noncurrent

            Day 1
                --> Move noncurrent version to Standard-IA

            Day 30
                --> Delete noncurrent version


    # Delete Markers:
        When a versioned object is deleted without specifying a Version ID:

            - S3 inserts a delete marker.
            - The delete marker becomes the current version.
            - The object appears deleted to normal clients.
            - Older data versions still exist.

        Restore:
            - Delete the delete marker.
            - A previous version becomes current again.

        Permanent deletion:
            - Requires deleting a specific Version ID.


    # MFA Delete:
        MFA Delete adds an MFA requirement to permanent version deletion.

        Purpose:
            - Protects against permanent deletion using compromised credentials.

        Requires:
            - Valid credentials.
            - MFA device token.

        Enabled through:
            - AWS CLI using root account credentials.

        Best for:
            - Compliance archives.
            - Financial backups.
            - Irreplaceable datasets.


    # S3 Object Lock:
        Object Lock provides WORM protection.

        WORM:
            --> Write Once, Read Many

        It prevents deletion or overwrite during the retention period.

        Two modes:

            1. Governance Mode
                - Protected by default.
                - Users with special IAM permission can override.

            2. Compliance Mode
                - Cannot be deleted or overwritten during retention.
                - Even administrators, root, or AWS Support cannot override.

        Retention methods:

            Retention Period
                --> Protect until a specific date.

            Legal Hold
                --> Protect indefinitely until an authorized user removes the hold.


    # S3 Replication:
        Replication automatically copies objects from a source bucket
        to a destination bucket.

        Requirements shown:
            - Versioning enabled on source bucket.
            - Versioning enabled on destination bucket.

        Types:
            CRR
                --> Cross-Region Replication.

            SRR
                --> Same-Region Replication.

        Use cases:
            - Geographic disaster recovery.
            - Compliance.
            - Global latency.
            - Cross-account copies.
            - Log aggregation.

        Important:
            - Existing objects are not replicated automatically.
            - Use S3 Batch Operations for existing data.
            - Delete markers are not replicated by default.
            - Destination can use a different storage class.


    # Versioning vs Lifecycle vs Replication:
        Versioning:
            - Same bucket.
            - Keeps multiple versions.
            - Protects against overwrite and delete.

        Lifecycle Policies:
            - Same bucket.
            - Automates transitions and expiration.
            - Helps control storage cost and retention.

        Replication:
            - Different bucket.
            - Copies objects to another bucket.
            - Adds geographic separation and resilience.


    # Quick Summary:
        1. Current Version
            --> Latest object version.

        2. Noncurrent Version
            --> Older version still stored and billed.

        3. Delete Marker
            --> Makes an object appear deleted without removing old versions.

        4. MFA Delete
            --> Requires MFA for permanent version deletion.

        5. Object Lock
            --> WORM protection against deletion or overwrite.

        6. Replication
            --> Copies objects automatically to another bucket.

        7. Lifecycle Rules
            --> Manage noncurrent versions and delete markers automatically.


    # Lecture Summary:
        "S3 Versioning keeps older object versions as noncurrent versions, which can
        be transitioned or deleted using lifecycle rules. Delete markers make objects
        appear deleted without removing old versions. MFA Delete and Object Lock add
        stronger protection against permanent deletion, while S3 Replication copies
        versioned objects to another bucket for resilience and separation."
